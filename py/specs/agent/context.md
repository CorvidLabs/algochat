## Context

Leif confirmed on 2026-10-29 (hi/agent.md) that any agent should be able to use AlgoChat as a bot through one shared core that starts in Python, self-hosted by its operator, with its own wallet and a key kept in an env var or local file on the bot host. This module is that core's first slice (algochat#43, tracker algochat#39).

Design choices that are not confirmed intent: refusing mnemonic files with group or other permission bits, refusing to choose when both environment variables are set, the variable names, the `*.mnemonic` and `.algochat-agent/` ignore patterns, and supporting only Ed25519 accounts for now. The mnemonic decoder is vendored so the package keeps `cryptography` as its only runtime dependency.

One-to-one replies (algochat#44, AGENT-5) add sending to the library itself, so a bot answers without a separate wallet tool. Design choices there, not confirmed intent: payments are built and signed in the library with no Algorand SDK; `HttpAlgodClient` and `HttpIndexerClient` use the standard library and have no default endpoint; replies use the section 9.2 reply format so every client can show what is being answered; a restarted bot learns what it already answered from its own replies on chain, with no local state file; notes it cannot open are skipped; a failing handler is reported and not retried, so one bad message cannot make the bot pay fees in a loop; the preview is cut by Python characters (TypeScript cuts by UTF-16 units, which differs only for characters outside the Basic Multilingual Plane).

Rooms and channels (algochat#45, AGENT-6, AGENT-7). Leif confirmed (hi/agent.md) that an owner or admin adds a bot and it joins at once without accepting (AGENT-7.d), that it works in a room's channels, each added separately by an admin (AGENT-7.g), that removing it is an ordinary removal with a new room key that also drops it from the room's channels (AGENT-7.c), and that it can leave (AGENT-7). Design choices, not confirmed intent: the protocol has no op for a member to remove themselves, so the bot leaves by posting a plain-text notice and stopping, and only an owner or admin can remove it and rotate the key (a protocol leave op would be a separate protocol change); room replies are plain text like Raven, and a room reply format is left to algochat#46; a restarted bot learns what it already answered from its join record and its own last post on chain, with no local state file (so a member message that confirmed before that post and was never answered stays unanswered after a restart); the counter follows Raven (highest seen in the epoch plus one); the hybrid session that opens a key delivery must come from the same account that sent it.

Reply policy (algochat#46, AGENT-8). Leif confirmed (hi/agent.md) that the bot replies only in the mode the room's admin chose (AGENT-8), within the rate limit set there (AGENT-8.b), never to another bot (AGENT-8.c), that `@name` and replying to its message are both mentions (AGENT-8.d), that the owner or an admin can change mode and limit at any time (AGENT-8.e), and that the bot declares its own slash commands (AGENT-8.f). Design choices, not confirmed intent: the bot reads the mode and limit from the room's current record each time it serves, so a change also covers messages it has not handled yet; every post in a room (replies, `/help` answers, command lists) counts toward the limit, except the final leave notice; a message over the limit is skipped, not queued, so the bot never answers late in a burst; a restarted bot counts its earlier posts by block time, and the window runs on chain time only (the newest block time read, carried forward with a monotonic clock), never the host clock; `send_room`, `reply_room`, `send_direct` and `reply` read the rooms again and refuse what the policy rules out; the command list is a plain-text room message (`Commands for @name:` and one `/command - description` line each), posted only in commands mode and only when it changed, rather than a new signed note type, so every implementation and Raven can read it with no protocol change; `/help` is always declared and answered with that list unless the operator handles it; a mention is `@` plus the bot's name in any case or its exact address, not inside an email address or a longer word; the bot treats an account as a bot when any of its rooms marks it, and applies that to one-to-one messages too; a bot added as a plain member has no mode and stays silent (there is no default mode, AGENT-8.a); the bot's own replies stay plain room text.
