- `REQ-agent-002`: `tests/test_agent.py::TestLoadMnemonic` (owner, ACL, symlink to a 0644 target, FIFO, non-UTF-8, both variables plus a path, fstat-and-read on one descriptor) and `TestTracebackLocals`.
- `REQ-agent-003`: `tests/test_agent.py::TestAgentCore`.
- `REQ-agent-004`: `tests/test_agent_direct.py` (an in-memory chain that decodes each signed payment), `tests/test_transaction.py` (transaction ids and signed bytes match `py-algorand-sdk` vectors), `tests/test_http_clients.py` (next-token paging, errors without the token, against a loopback server).
- `REQ-agent-006`: `tests/test_agent_policy.py` (the in-memory chain and a fake clock): mentions by name, address and reply; email addresses and longer words are not mentions; section 9.1 and 9.2 room text; command parsing with `/command@name`; the command list and its size limit; name and command checks; every-message mode skipping another bot; a plain-member bot staying silent; commands mode posting its list once, answering declared commands and `/help`, and posting a new list when the commands change; an operator `help` replacing the built-in one; an admin and the owner changing the mode; the rate limit across a restart and after the owner raises it; a chain clock four hours behind the host (no fake clock) that keeps the limit across a restart, and one ahead that opens the window again; `reply_room` refusing a message the policy skips, following a mode change made after the message was read, and deciding from-bot from the rooms rather than the message; `send_room` and `reply_room` sharing one window, also after a restart; `send_room` refusing a no-mode room; `send_direct` and `reply` refusing a room bot before paying; a full limit holding back the command list; a one-to-one message from a room bot left unanswered.
- `REQ-agent-005`: `tests/test_agent_rooms.py` (the in-memory chain with an owner drafting records through the library, `tests/room_support.py`): joining without a request, refused deliveries (plain member, stranger, set-name record, a session from another account), read and reply, no answer after a restart or for history before the join, non-members and copied notes, a new key after a member removal, waiting for a key, channels and their parent, removal from a room and its channels, leaving and restarting, handler errors, and the signed PQ key.

- `REQ-agent-007`: `tests/test_agent_adapters.py` (the in-memory chain and loopback HTTP and HTTPS receivers from `tests/webhook_support.py`): every CLI command has an MCP tool with the same parameters; MCP initialize, tools, errors and stdio; room tools refuse what the policy skips (not mentioned, another bot, rate limit) and answer the rest; `reply` refuses a room bot; URL rules for loopback, plain http, https with and without a secret, and credentials; signatures and timestamps; secret loading; the bridge signs, ignores proxies, refuses redirects and oversize or odd answers, and checks certificates; `serve` sends the webhook only what the policy allows; the CLI's missing-settings error carries no key.

Unit-test fixtures use public, non-secret seeds and call no network.

`tests/test_agent_localnet.py` (marker `localnet`) runs the same requirements against a real local Algorand network (algod, kmd, indexer) and is skipped when none is running; `ALGOCHAT_REQUIRE_LOCALNET=1` turns the skip into a failure. Accounts are generated per test and funded only from the localnet's own KMD wallet; the helpers refuse any non-local genesis id. See `docs/localnet-testing.md`.

- `REQ-agent-001`: `test_bot_account_from_env_mnemonic_matches_funded_localnet_account` (algod accepts transactions signed with the decoded seed), `test_mnemonic_decoding_matches_goal_export` (cross-check against go-algorand's `goal`, when `ALGOCHAT_LOCALNET_ALGOD_DATA` is set).

- `REQ-agent-004`: `tests/test_agent_direct_localnet.py`. - `REQ-agent-005`: `tests/test_agent_rooms_localnet.py`. An owner makes a room and a channel on LocalNet and adds the bot with op 13; a key delivered by a plain member is ignored. After a member removal the bot answers under the epoch 2 key; it leaves the channel and a fresh core stays out; after its own removal it answers nothing and cannot post. Every implementation opens every bot and person room note and reduces both chains to the same state; Swift does the same through `swift test --filter AgentRoomsLocalnetTests`, which must run, not skip. `test_removing_the_bot_from_the_room_takes_it_out_of_a_channel_it_never_left` covers parent removal.
- `REQ-agent-006`: `tests/test_agent_policy_localnet.py`. An owner makes a room on LocalNet with an admin, another bot, and our bot in mentions mode (2 per 20 s). TypeScript, Go, Rust, Python and Kotlin write messages with their own tools: the bot answers only mentions, skips the third mention for the rate limit and the other bot's message; a restarted bot still counts its replies from their block times; a reply to the bot's message counts as a mention. The admin switches it to commands mode with op 14: it posts its command list, answers `/echo` and `/help@helper`, skips other text and `/echo@other`; a fresh core does not post the list again; the limit holds. The owner switches it to every message; the other bot is still skipped. A one-to-one message from the other bot is not answered and one from a person is. Every implementation opens every bot and person note and reduces the chain with both bots' modes and limits; Swift does the same through `swift test --filter AgentRoomsLocalnetTests`, which must run, not skip.
- `REQ-agent-007`: `tests/test_agent_adapters_localnet.py`. The real `algochat-agent` CLI and its MCP server run as processes with the bot's mnemonic only in their environment. TypeScript, Go and Rust write room messages; over MCP, `tools/list` has every command, `read_rooms` reports each skip reason and `reply_room` refuses the unmentioned and the bot's message and answers the mention. `serve --once` with a signed loopback webhook sends it only the person's one-to-one message and the Kotlin-written mention, skips the Python-written unmentioned message and the other bot, and posts both answers. In commands mode the CLI posts the command list, then leaves the room. Every implementation opens every bot and person note and reduces the chain; Swift does the same through `swift test --filter AgentRoomsLocalnetTests`, which must run, not skip. No CLI or MCP output carries the key.
